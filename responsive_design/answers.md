# Ответы на вопросы для самоконтроля

## 1. Что такое Viewport meta tag и почему он важен для адаптивного дизайна?

`<meta name="viewport" content="width=device-width, initial-scale=1.0">` — мета-тег, который сообщает браузеру, как масштабировать страницу на устройстве.

- `width=device-width` — ширина страницы равна ширине экрана устройства (а не фиксированной десктопной ширине ~980px).
- `initial-scale=1.0` — начальный масштаб 1:1, без принудительного увеличения.

Без этого тега мобильные браузеры отображают страницу в «десктопном» масштабе, сжимая весь контент, из-за чего медиа-запросы и адаптивная вёрстка работают неправильно.

## 2. Какие основные подходы к созданию адаптивных макетов вы использовали в работе (Fluid, Adaptive, Responsive)?

- **Fluid (резиновый)** — размеры задаются в относительных единицах (`%`, `rem`, `vw`, `fr`), контейнер `width: 100%; max-width: 1200px`. Макет плавно тянется при изменении окна.
- **Adaptive (адаптивный)** — используются фиксированные контрольные точки (брейкпоинты) и медиа-запросы; макет «перестраивается» на определённых разрешениях.
- **Responsive (отзывчивый)** — комбинация fluid и adaptive: плавное масштабирование + перестройка на брейкпоинтах, плюс адаптивные изображения и типографика.

В данной работе использован **responsive-подход**: резиновый контейнер, `clamp()` для шрифтов, медиа-запросы на 1024px, 768px, 480px и адаптивные изображения.

## 3. Как работает Mobile First подход и в чем его преимущества перед Desktop First?

**Mobile First** — сначала пишутся стили для мобильных устройств (базовые), а затем с помощью `min-width` медиа-запросов добавляются стили для более широких экранов.

**Преимущества перед Desktop First:**
- Проще код: базовые стили — самые лёгкие, а усложнения добавляются по мере роста экрана.
- Меньше лишних переопределений (в Desktop First приходится «сбрасывать» десктопные стили для мобильных).
- Быстрее загрузка на мобильных (основной трафик) — меньше CSS применяется сразу.
- Лучше соответствует принципу прогрессивного улучшения.

## 4. Какие единицы измерения наиболее предпочтительны для адаптивной верстки и почему (%, rem, em, vw/vh)?

- **`%`** — для ширины контейнеров, изображений, флекс-элементов; позволяет резиново подстраиваться под родителя.
- **`rem`** — для шрифтов, отступов, размеров компонентов; зависит от `font-size` корневого элемента, легко масштабируется глобально.
- **`em`** — для отступов внутри компонента относительно его шрифта; удобно для «самомасштабирующихся» блоков.
- **`vw`/`vh`** — для секций на всю ширину/высоту экрана, для `clamp()` в типографике.

Не рекомендуется использовать `px` для всего — это ломает масштабирование. Лучше комбинировать: `rem` для типографики и отступов, `%`/`fr` — для сеток, `vw` — для адаптивных заголовков.

## 5. Как функция clamp() помогает создавать адаптивную типографику?

`clamp(min, preferred, max)` задаёт значение, которое **плавно меняется** между минимумом и максимумом в зависимости от вьюпорта, не выходя за пределы.

**Пример:**
```css
.hero h2 {
    font-size: clamp(1.5rem, 5vw, 2.5rem);
}
```
- На маленьком экране шрифт будет не меньше `1.5rem`.
- На среднем — масштабируется как `5vw`.
- На большом — не больше `2.5rem`.

Это позволяет отказаться от отдельных медиа-запросов для шрифтов и получить плавную адаптивную типографику.

## 6. Какие основные брейкпоинты вы использовали и как определили эти значения?

Использованы:
- **1024px** — планшеты в горизонтальной ориентации / небольшие ноутбуки: сетка преимуществ становится 2-колоночной, контент с сайдбаром перестраивается в колонку.
- **768px** — планшеты в портретной ориентации и крупные телефоны: появляется кнопка-гамбургер, меню становится выпадающим.
- **480px** — маленькие смартфоны: уменьшается шрифт, сетка преимуществ в одну колонку, уменьшаются отступы.

Значения выбраны по типовым размерам устройств и стандартным практикам (Bootstrap, Tailwind). Их стоит уточнять по реальной статистике посещений и дизайн-макетам.

## 7. Как медиа-запросы @media помогают создавать адаптивные стили? Приведите пример синтаксиса.

`@media` позволяет применять CSS-правила только при выполнении условия (ширина экрана, ориентация, плотность пикселей и т.д.).

**Синтаксис:**
```css
@media (max-width: 768px) {
    .nav-menu {
        display: none;
    }
}
```

Можно комбинировать условия:
```css
@media (min-width: 768px) and (max-width: 1024px) {
    /* стили только для планшетов */
}
```

Также поддерживаются `min-width` (Mobile First), `orientation: landscape`, `prefers-color-scheme` и др.

## 8. В чем разница между max-width и min-width в медиа-запросах и когда использовать каждый?

- `@media (max-width: 768px)` — стили применяются, когда ширина экрана **не больше** 768px. Используется в **Desktop First** подходе (сначала десктоп, потом упрощаем).
- `@media (min-width: 768px)` — стили применяются, когда ширина **не меньше** 768px. Используется в **Mobile First** подходе (сначала мобильные, потом усложняем).

**Правило:** выбирайте один подход для проекта, чтобы избежать конфликтов. Mobile First (`min-width`) считается более современным и удобным.

## 9. Как сделать изображения адаптивными и какие CSS-свойства для этого используются?

Основные приёмы:
```css
img {
    max-width: 100%;
    height: auto;
    display: block;
}
```
- `max-width: 100%` — изображение не выходит за пределы контейнера.
- `height: auto` — сохраняет пропорции.
- `display: block` — убирает лишний inline-отступ снизу.

Дополнительно:
- `object-fit: cover / contain` — для вписывания в заданные размеры без искажений.
- `srcset` и `sizes` в HTML — для загрузки разных версий изображения под разные экраны.
- `<picture>` с `<source media="...">` — для арт-дирекшена.
- `aspect-ratio` — для фиксации пропорций без «прыжков» при загрузке.

## 10. Какие инструменты браузера помогают тестировать и отлаживать адаптивный дизайн?

- **Device Mode / Responsive Design Mode** (Chrome DevTools, Firefox) — эмуляция размеров экранов, устройств, DPR.
- **Панель Elements / Inspector** — просмотр и изменение CSS в реальном времени, проверка медиа-запросов.
- **Панель Network** — проверка загрузки адаптивных изображений (`srcset`), throttling скорости.
- **Lighthouse** — аудит производительности и адаптивности.
- **CSS Overview** (Chrome) — обзор использованных медиа-запросов и цветов.
- **Ruler / измерение** — проверка размеров и отступов.
- **Эмуляция touch-событий** — проверка работы мобильного меню и hover-эффектов.
