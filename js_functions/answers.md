# Ответы на вопросы для самоконтроля — Практическая работа №10

## 1. Function Declaration и Function Expression: hoisting
**Function Declaration** (`function foo() {}`) поднимается целиком: и имя, и тело доступны с начала области видимости, поэтому функцию можно вызвать до её объявления в коде.
**Function Expression** (`const foo = function () {}` или стрелочная функция) — это обычное присваивание значения переменной. Поднимается только объявление переменной: `var` будет `undefined` (вызов даст `TypeError: foo is not a function`), а `let`/`const` находятся в «временной мёртвой зоне» (TDZ) и дадут `ReferenceError` при обращении до строки с объявлением.

```js
hello();            // работает
function hello() {}

bye();              // ReferenceError (TDZ)
const bye = () => {};
```

## 2. Rest parameters и объект arguments
`...args` собирает «оставшиеся» аргументы в **настоящий массив** (`Array`), у которого есть `map`, `filter`, `reduce` и т.д. Rest можно использовать с любым количеством именованных параметров перед ним (`function f(a, ...rest)`), он работает и в стрелочных функциях.
`arguments` — **array-like объект** (есть `length` и индексы, но нет методов массива), содержит все переданные аргументы, недоступен в стрелочных функциях и в строгом режиме не связан с параметрами. Rest parameters — современная и более предсказуемая замена: `sum(...numbers)` проще, чем `Array.from(arguments)`.

## 3. Замыкание и лексическая область видимости
**Лексическая область видимости** означает, что доступные функции переменные определяются местом, где функция *написана*, а не где вызвана. **Замыкание** — это функция вместе со ссылкой на окружение, в котором она создана. Поэтому функция «помнит» внешние переменные, даже когда внешняя функция уже завершилась.
В `secretMessage(password, message)` возвращаемая функция продолжает видеть `password` и `message`, хотя снаружи получить к ним доступ нельзя — так замыкание обеспечивает приватность данных. Так же устроены `memoize` (приватный кэш), `debounce` (приватный таймер) и `createValidator` (сохранённые опции).

## 4. Рекурсия или итерация
**Рекурсия** подходит для задач с естественной вложенной/древовидной структурой: обход дерева и файловой системы, вложенные объекты, «разделяй и властвуй» (быстрая сортировка, слияние), перебор вариантов (backtracking). Код короче и ближе к математическому определению. Минусы: расход памяти на стек вызовов (риск `RangeError: Maximum call stack size exceeded`), накладные расходы на вызовы, наивные реализации могут быть экспоненциально медленными (Фибоначчи без мемоизации). JavaScript не гарантирует оптимизацию хвостовой рекурсии.
**Итерация** (циклы) быстрее и экономнее по памяти, не ограничена глубиной стека; подходит для простых линейных задач. Минусы: для деревьев и сложных структур код может стать громоздким (приходится вручную вести стек).

## 5. Функции высшего порядка
Функция высшего порядка — это функция, которая **принимает другую функцию как аргумент** и/или **возвращает функцию**. Это возможно, потому что функции в JavaScript — значения первого класса. В работе такими являются `compose`, `curry`, `memoize`, `debounce`, `throttle`, `myMap`, `myFilter`, `myReduce`.
Среди встроенных методов массивов: `map`, `filter`, `reduce`, `reduceRight`, `forEach`, `find`, `findIndex`, `some`, `every`, `flatMap`, `sort` (с компаратором). Они позволяют описывать *что* нужно сделать с данными, а не *как* перебирать их.

## 6. Каррирование
Каррирование превращает функцию от нескольких аргументов в цепочку функций от одного (или нескольких) аргумента: `f(a, b, c)` → `f(a)(b)(c)`. Преимущества:
- **частичное применение**: `const add10 = curry(add)(10)` — заготовка для переиспользования;
- удобная **композиция** функций (`compose`, `pipe`) — каждая функция в цепочке принимает один аргумент;
- более читаемый и декларативный код, например `arr.map(multiplyBy(2))`;
- меньше дублирования при настройке общих параметров (форматтеры, логгеры, обработчики событий).

## 7. Мемоизация
Мемоизация — кэширование результатов функции по её аргументам: при повторном вызове с теми же аргументами возвращается сохранённое значение без повторных вычислений. Кэш хранится в замыкании (в моей реализации — `Map`, ключ — `JSON.stringify(args)`).
Наиболее эффективна для **чистых функций** (результат зависит только от аргументов, нет побочных эффектов), **дорогих вычислений** и **повторяющихся вызовов** с одними и теми же данными: рекурсивные алгоритмы с перекрывающимися подзадачами (Фибоначчи: O(2ⁿ) → O(n)), динамическое программирование, тяжёлые расчёты и преобразования.
Не подходит для функций с побочными эффектами или случайностью (`Math.random`, `Date.now`), а также когда аргументы почти никогда не повторяются — кэш только съедает память (его размер стоит ограничивать).

## 8. Debounce и throttle
Обе техники ограничивают частоту вызова функции, но по-разному:
- **debounce** откладывает вызов до тех пор, пока события не прекратятся на `delay` мс. Серия событий → один вызов в конце. Применение: поиск при вводе в поле (запрос после паузы в печати), валидация формы, пересчёт после изменения размера окна, автосохранение.
- **throttle** гарантирует, что функция выполнится не чаще одного раза за `interval` мс, независимо от того, сколько событий пришло. Серия событий → регулярные вызовы во время всего потока событий. Применение: обработка `scroll`, `mousemove`, drag-and-drop, анимации, защита кнопки от частых нажатий, подгрузка при прокрутке.

Коротко: debounce — «подожди, пока закончат», throttle — «не чаще, чем раз в N мс».

## 9. Функции-генераторы (function*)
Обычная функция выполняется от начала до конца и возвращает одно значение. **Генератор** (`function*`) при вызове не выполняет тело, а возвращает *итератор*. Выполнение можно приостанавливать на `yield` и возобновлять методом `next()`; каждый `yield` отдаёт очередное значение, при этом состояние локальных переменных сохраняется между вызовами. В `next(value)` можно передавать данные обратно внутрь генератора.
Преимущества: ленивые вычисления (значения вычисляются по мере запроса), возможность описывать бесконечные последовательности, удобная реализация итераторов (`for...of`, spread), основа для асинхронных паттернов (`async/await` исторически строился на генераторах).

```js
function* fib() {
    let [a, b] = [0, 1];
    while (true) { yield a; [a, b] = [b, a + b]; }
}
const it = fib();
it.next().value; // 0
it.next().value; // 1
it.next().value; // 1
```

## 10. Принципы функционального программирования в работе
- **Функции первого класса и функции высшего порядка** — `compose`, `curry`, `memoize`, `debounce`, `throttle` принимают и возвращают функции.
- **Чистые функции** — `sum`, `myMap`, `myFilter`, `myReduce`, `createUser` зависят только от аргументов и не изменяют внешнее состояние.
- **Иммутабельность** — `myMap` и `myFilter` создают новый массив и не меняют исходный.
- **Замыкания** — `secretMessage`, `memoize`, `debounce`, `throttle`, `createValidator` хранят состояние в приватной области видимости.
- **Композиция** — сложное поведение собирается из простых функций (`compose`, `pipe`).
- **Декларативность** — описываем, что нужно получить, а не как перебирать данные.

Преимущества: код проще тестировать (нет скрытого состояния), легче переиспользовать и читать, меньше ошибок из-за побочных эффектов, функции легко комбинируются и кэшируются.
