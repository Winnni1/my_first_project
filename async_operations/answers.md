# Ответы на вопросы для самоконтроля — ПР13

1. **`.then().catch()` и `async/await` с `try/catch`.** Оба способа работают с промисами. Цепочки `then/catch` удобны для коротких преобразований и передачи результата между шагами. `async/await` делает последовательный код более похожим на обычный и проще читается; `try/catch` удобно группирует обработку ошибок. Можно использовать оба подхода вместе.

2. **`Promise.all`.** Запускает переданные промисы и возвращает промис с массивом результатов, когда все успешно завершатся. Если хотя бы один промис отклонён, общий промис отклоняется с этой ошибкой (остальные операции при этом автоматически не отменяются).

3. **`Promise.all`, `Promise.race`, `Promise.allSettled`.** `all` ждёт успеха всех операций и возвращает результаты; подходит для загрузки нескольких частей данных. `race` возвращает результат/ошибку первого завершившегося промиса; подходит, например, для таймаута. `allSettled` ждёт завершения всех, независимо от исхода, и даёт статус каждого; удобно собирать статистику по успешным и неуспешным задачам.

4. **Retry с экспоненциальной задержкой.** Повторять операцию после ошибки, увеличивая ожидание, например 250, 500, 1000, 2000 мс. Ограничить число попыток и после исчерпания лимита пробросить последнюю ошибку. В этой работе это реализовано в `retryWithBackoff`.

5. **Race condition.** Состояние гонки — ситуация, когда результат зависит от того, какая асинхронная операция завершится раньше, и порядок непредсказуем. Снижают риск: последовательное `await`, отмена устаревших запросов через `AbortController`, проверка актуальности результата, блокировка повторного запуска и корректная синхронизация общего состояния.

6. **Кэширование асинхронных запросов.** Сохраняет ответ по ключу (обычно URL или параметрам), чтобы повторно не выполнять запрос. Стратегии: кэш на время с TTL, кэширование только успешных ответов, очистка/ограничение размера (LRU), обновление в фоне, ручная инвалидация. В примере используется `Map` на время жизни функции-кэша.

7. **Оптимизация множественных операций.** Выполнять независимые запросы параллельно (`Promise.all`/`allSettled`), ограничивать конкурентность при большом числе задач, кэшировать, избегать повторных запросов, использовать пагинацию, таймауты и отмену ненужных запросов, показывать состояние загрузки и измерять производительность.

8. **Ошибки в цепочках промисов.** Добавлять `catch` в подходящем месте, возвращать промисы из `then`, не игнорировать ошибки, при обработке не скрывать их без причины. Если ошибка должна идти дальше, повторно выбросить её (`throw error`). Для `async/await` использовать `try/catch` и обрабатывать либо пробрасывать ошибку дальше.

9. **Преимущества `async/await`.** Более читаемый последовательный код, простая обработка ошибок через `try/catch`, удобное выполнение условных циклов и промежуточных шагов. В отличие от callback-ов, меньше вложенности. `async/await` основан на промисах и не делает операции синхронными.

10. **Отладка асинхронного кода.** Использовать DevTools: Console для ошибок и логов, Sources для breakpoints и пошагового выполнения, Network для статуса/времени запросов и содержимого, Performance для анализа задержек. Проверять обработчики rejection, сетевые ошибки, тайминги и порядок завершения операций.
