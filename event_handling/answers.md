# Ответы на вопросы для самоконтроля

1. **В чем разница между `event.preventDefault()` и `event.stopPropagation()`?**  
   `preventDefault()` отменяет стандартное действие браузера (например, переход по ссылке или отправку формы), но не останавливает распространение события. `stopPropagation()` прекращает распространение события по DOM, но не отменяет стандартное действие. Их применяют для разных целей, иногда вместе.

2. **Как работает делегирование событий и какие преимущества?**  
   Обработчик ставится на родительский элемент. Внутри него по `event.target` или `closest()` определяется элемент, на котором произошло событие. Это удобно для динамически создаваемых элементов, уменьшает число обработчиков и упрощает поддержку списка.

3. **Какие фазы жизненного цикла события существуют?**  
   Capturing — событие идёт от корня DOM к целевому элементу; target — обработка на самом целевом элементе; bubbling — событие всплывает от цели к корню. Фаза влияет на порядок срабатывания обработчиков; capturing можно включить третьим параметром `addEventListener` или в объекте options.

4. **Разница между `event.target` и `event.currentTarget`?**  
   `target` — исходный элемент, на котором возникло событие (может быть вложенным). `currentTarget` — элемент, на котором сейчас выполняется обработчик. При делегировании обычно используют `target` для поиска вложенного элемента, а `currentTarget` — чтобы получить контейнер.

5. **Как создать и запустить кастомное событие?**  
   Создают `new CustomEvent('имя', { detail: данные, bubbles: true, cancelable: true })`, затем вызывают `dispatchEvent()` у нужного элемента. В `detail` передают произвольные данные; опции задают всплытие и возможность отмены.

6. **Что такое debounce и throttle?**  
   Debounce откладывает выполнение до тех пор, пока поток вызовов не прекратится на заданный промежуток времени. Подходит для поиска по вводу и сохранения после редактирования. Throttle ограничивает частоту выполнения, например, не чаще одного раза за интервал; подходит для scroll, resize и частых событий мыши.

7. **Какие методы удаляют обработчики и почему это важно?**  
   Обработчик удаляют через `removeEventListener()` с тем же типом события, ссылкой на функцию и параметром capture. Также можно использовать `AbortController` с `signal`. Удаление ненужных обработчиков предотвращает повторное выполнение, утечки памяти и нежелательные действия.

8. **Как обрабатывать ошибки загрузки ресурсов?**  
   Для изображения или скрипта используют события `load` и `error`; у некоторых ресурсов также есть `loadstart`/`loadend` в соответствующих API. В обработчике `error` показывают понятное сообщение, предлагают повторить действие или используют резервный ресурс. Для `fetch` ошибки сети и HTTP-статусы проверяются через Promise/`try...catch`.

9. **Разница между `addEventListener` и назначением через `onclick`?**  
   `addEventListener` позволяет назначать несколько обработчиков одного события, выбирать фазу capturing и использовать options (`once`, `passive`, `signal`), а также легко удалять обработчик. Присваивание `onclick` хранит только один обработчик в свойстве и может перезаписать предыдущий.

10. **Как оптимизировать работу с большим количеством событий?**  
    Использовать делегирование, debounce/throttle, пассивные обработчики для событий прокрутки там, где это допустимо, удалять обработчики после завершения работы, не выполнять тяжёлые операции синхронно, объединять DOM-изменения, использовать `requestAnimationFrame` для визуальных обновлений и избегать лишних обработчиков.
