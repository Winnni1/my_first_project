# Ответы на вопросы для самоконтроля — Практическая работа №9

## 1. Разница между O(n) и O(n²)
O(n) — время растёт пропорционально размеру входных данных: удвоили данные — время выросло примерно вдвое. Примеры: поиск максимума (`findMax`), линейный поиск, удаление дубликатов через `Set`, разворот строки.
O(n²) — время растёт пропорционально квадрату размера: при удвоении данных время вырастает примерно в 4 раза. Обычно это вложенные циклы по одним и тем же данным. Примеры: пузырьковая сортировка, сортировка выбором, сравнение всех пар элементов. На 10 000 элементов O(n) — около 10 000 операций, O(n²) — около 100 000 000.

## 2. Бинарный поиск и почему O(log n)
Работает только на отсортированном массиве. Берём средний элемент: если он равен искомому — готово; если меньше искомого — продолжаем поиск в правой половине, если больше — в левой. Каждый шаг отбрасывает половину оставшихся элементов: n → n/2 → n/4 → … → 1. Число делений пополам до единицы — это log₂ n, поэтому сложность O(log n). Для 1 000 000 элементов нужно не более ~20 сравнений.

## 3. Пузырьковая сортировка: плюсы и минусы
Плюсы: очень простая в написании и понимании; сортирует «на месте» (O(1) доп. памяти); устойчивая (равные элементы не меняют порядок); с флагом `swapped` на уже отсортированном массиве работает за O(n).
Минусы: O(n²) в среднем и худшем случаях — на больших массивах очень медленная; делает много обменов. Быстрые алгоритмы (быстрая сортировка, сортировка слиянием, пирамидальная) работают за O(n log n). На практике пузырёк используют только для обучения или совсем маленьких массивов.

## 4. Оптимизация проверки на простоту
- Проверять делители только до √n (`i * i <= n`), а не до n — сложность O(√n).
- Сразу отсеивать числа < 2 и чётные числа, дальше перебирать только нечётные делители (в 2 раза меньше итераций).
- Можно проверять делители вида 6k ± 1 (ускорение примерно в 3 раза).
- Для множества чисел в диапазоне — решето Эратосфена (O(n log log n)).
- Для очень больших чисел — вероятностные тесты (Миллера—Рабина, Ферма).

## 5. Рекурсивный и итеративный Фибоначчи
Наивная рекурсия `fib(n) = fib(n-1) + fib(n-2)` пересчитывает одни и те же значения многократно: время O(2ⁿ), а также глубина стека O(n) — возможен переполнение стека. Итеративная версия (цикл, как в `fibonacci`) считает каждое число один раз: O(n) по времени и без глубокой рекурсии. Рекурсию можно ускорить мемоизацией (кэшем) до O(n), но итеративный вариант всё равно проще и экономнее по памяти.

## 7. Алгоритм Евклида для НОД
Основан на свойстве: НОД(a, b) = НОД(b, a mod b), а НОД(a, 0) = a. Повторяем замену (a, b) → (b, a % b), пока b не станет 0; тогда a — искомый НОД. Например, НОД(54, 24): (54, 24) → (24, 6) → (6, 0) → 6. Эффективен, потому что остаток от деления уменьшается как минимум вдвое каждые два шага, поэтому число шагов O(log(min(a, b))) — гораздо быстрее, чем перебор всех возможных делителей.

## 8. Edge cases для массивов
- Пустой массив (`findMax([])`, `bubbleSort([])`, `binarySearch([], x)`).
- Массив из одного элемента.
- Все элементы одинаковые / много дубликатов.
- Отрицательные числа и нули.
- Уже отсортированный и обратно отсортированный массив.
- Элемент не найден, элемент на границах (первый/последний).
- Некорректный вход (не массив, `null`, `undefined`), смешанные типы.
- Не изменять исходный массив (в `bubbleSort` работаем с копией).

## 9. Улучшение удаления дубликатов для больших массивов
Наивное решение с `indexOf`/`includes` внутри цикла работает за O(n²). Использование `Set` (или объекта/`Map`) даёт проверку наличия за O(1) и общую сложность O(n) — именно так сделано в `removeDuplicates`. Короткий вариант: `[...new Set(arr)]`. Для очень больших данных можно обрабатывать потоком/частями, чтобы не держать всё в памяти. Если нужно сохранить порядок — `Set` сохраняет порядок вставки. Для массивов объектов используют ключ (например, `id`) в `Map`.

## 10. Принципы чистого кода
- Понятные, говорящие имена функций и переменных (`isPrime`, `findLongestWord`).
- Одна функция — одна задача.
- Ранние возвраты и проверка входных данных вместо глубокой вложенности.
- Отсутствие «магических» значений: наборы символов вынесены в именованные константы.
- Комментарии о сложности алгоритмов и пояснения неочевидных мест.
- Отсутствие побочных эффектов: `bubbleSort` не изменяет исходный массив.
- Единый стиль форматирования и отступов, `const`/`let` вместо `var`.
- Тесты на обычные и крайние случаи.
